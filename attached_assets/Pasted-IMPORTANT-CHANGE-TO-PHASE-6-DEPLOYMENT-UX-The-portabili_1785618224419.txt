IMPORTANT CHANGE TO PHASE 6 DEPLOYMENT UX

The portability architecture from the previous task is correct, but I do NOT
want the administrator/end user to interact with PowerShell scripts, command
prompts, JSON files, or manual configuration during normal installation.

The final product must feel like a professional Windows application installer.

============================================================
PRIMARY REQUIREMENT
============================================================

The normal installation experience should be:

1. Administrator receives ONE installer.
2. Double-clicks it.
3. Windows installation wizard opens.
4. Click Next.
5. Installer automatically detects as much as possible.
6. Administrator enters only environment-specific values that cannot be
   discovered automatically.
7. Click Install.
8. Installer configures everything.
9. Installation finishes.
10. Laserfiche Dashboard works.

NO normal-use PowerShell commands.

NO CMD commands.

NO manually editing JSON.

NO manually copying JavaScript files.

NO manually editing Browse.aspx.

NO manually registering the Desktop extension.

NO manually creating IIS sites.

NO source-code modifications.

NO rebuild on the destination machine.

PowerShell scripts may exist internally for development/build automation if
absolutely necessary, but they must NOT be part of the normal administrator
installation workflow.

============================================================
1. CREATE A PROFESSIONAL BOOTSTRAPPER / SETUP EXE
============================================================

Instead of expecting the administrator to directly manage MSI configuration,
create a proper Windows setup experience.

Preferred final deliverable:

LFDashboard-Setup.exe

The EXE should bootstrap/install the required MSI/components.

Use an appropriate Windows installer technology compatible with the existing
WiX v4 work.

Investigate whether WiX Burn / WiX Bundle is appropriate.

The installer should provide a graphical wizard.

Do not create a custom installer framework unnecessarily if WiX already
supports the required behavior.

============================================================

============================================================

Create a simple configuration wizard.

Suggested pages:

Page 1:
Welcome

Laserfiche Dashboard Setup

- IIS
- ASP.NET Core Hosting Bundle

Laserfiche Web Client      Detected

Do not invent duplicate configuration settings.

Page 4:

Page 5:

============================================================
3. AUTOMATIC CONFIGURATION
============================================================

The installer must internally create/update:

%ProgramData%\Dashboard\laserfiche.config.json

%ProgramData%\Dashboard\extension.config.json

using the values entered in the wizard.

The administrator should NOT have to open these files.

Preserve existing files during upgrades unless the administrator explicitly
changes configuration through the installer.

============================================================
4. AUTOMATIC IIS CONFIGURATION
============================================================

The installer should automatically:

- install/copy the Dashboard application
- create the IIS Application Pool
- create/configure the IIS site/application
- configure physical path
- configure port/binding
- configure permissions
- configure ASP.NET Core hosting
- start the site
- verify the application starts

Do not require IIS Manager for normal installation.

============================================================
5. AUTOMATIC DESKTOP CLIENT INTEGRATION
============================================================

If Laserfiche Desktop Client is detected and the administrator selects:

"Add Dashboard button to Laserfiche Desktop Client"

the installer should automatically perform the equivalent of the current:

Dashboard.DesktopExtension.exe --setup

internally.

The user must NOT run this command manually.

Configure:

extension.config.json

with the Dashboard URL entered in the setup wizard.

After installation the Laserfiche Desktop Client should show the Dashboard
button after restart.

============================================================
6. AUTOMATIC WEB CLIENT INTEGRATION
============================================================

This is extremely important.

Currently Web Client deployment requires:

Deploy-WebClientButton.ps1
copying lf-dashboard-button.js
editing Browse.aspx

I DO NOT want the administrator doing any of this manually.

Move this behavior behind the installer.

If Laserfiche Web Client is detected and the administrator selects:

"Add Dashboard button to Laserfiche Web Client"

the installer must:

1. Detect the correct Web Client installation.
2. Locate Web Files.
3. Locate Browse.aspx.
4. Locate assets/custom.
5. Back up Browse.aspx safely.
6. Install lf-dashboard-button.js.
7. Configure the Dashboard URL automatically.
8. Add the required script tag to Browse.aspx idempotently.
9. Ensure the script tag exists exactly once.
10. Verify the installed JavaScript file exists.
11. Preserve the currently working repository detection:
    WebAccessRepositoryName.
12. Preserve the current single-tab behavior.
13. Preserve the Angular-safe DOM implementation.

The administrator should never manually modify Browse.aspx.

IMPORTANT:

Before modifying a vendor Laserfiche file, create a backup.

Example:

Browse.aspx.lfdashboard.backup

The integration must be idempotent.

Running Repair or Upgrade must NOT add:

<script ...>

multiple times.

============================================================
7. SAFE WEB CLIENT UPGRADE HANDLING
============================================================

Laserfiche upgrades may replace Browse.aspx.

Design for this.

The installer should be able to Repair the Web Client integration.

For example:

Apps & Features
    ->
Laserfiche Dashboard
    ->
Modify / Repair

or rerunning:

LFDashboard-Setup.exe

should detect:

Dashboard Web Client integration missing

and restore it safely.

Do not require PowerShell.

============================================================

16. UNINSTALL
============================================================

Apps & Features should show:

Laserfiche Dashboard

Uninstall should:

remove Dashboard binaries
remove IIS configuration created by Dashboard
remove Desktop Client registration
remove Dashboard Web Client JavaScript
remove ONLY the Dashboard script reference from Browse.aspx

DO NOT remove unrelated Laserfiche customizations.

DO NOT delete user configuration/credentials by default.

Keep:

%ProgramData%\Dashboard\

unless the administrator explicitly chooses:

"Remove configuration and data"

if implementing such an option.
