==================================================
INVESTIGATE WHY THE VISIBLE BUTTON CANNOT RECEIVE CLICKS
==================================================

Do not assume that merely calling addEventListener("click", ...) solves the problem.

Audit the actual generated DOM structure and CSS behavior of the Dashboard element.

Investigate all likely causes, including:

1. Another Laserfiche element is physically overlaying the Dashboard button.

2. The Dashboard element or one of its parents has:

pointer-events: none

3. A transparent element is positioned above the button because of:

position
z-index
absolute/fixed positioning

4. The button was inserted inside a Laserfiche/Angular element that intercepts pointer events.

5. Laserfiche has a parent click handler calling:

preventDefault()
stopPropagation()
stopImmediatePropagation()

6. Laserfiche replaces/clones the navbar DOM after our handler is attached.

7. The visible element is not the same DOM node that owns the click handler.

8. An invisible Angular/bootstrap/navbar element is covering the button.

9. The element type or markup being injected is incompatible with the navbar.

10. CSS classes copied from Laserfiche are making the element visually correct but functionally non-interactive.

11. The button is being recreated after initialization without its event listener.

12. A capture/bubble phase conflict is preventing our handler from executing.

13. The custom script is executing in an unusual Laserfiche JavaScript context.

Determine the ACTUAL cause from the implementation instead of applying random workarounds.

==================================================
MAKE THE BUTTON DEFINITELY INTERACTIVE
==================================================

The final Dashboard control must be a genuinely interactive element.

Prefer semantic markup such as:

<button type="button">

or:

<a href="..." role="button">

depending on what integrates most safely with the existing Laserfiche navbar.

It must have a stable identifier, for example:

id="lf-dashboard-button"

and/or:

data-lf-dashboard-button="true"

Ensure the final element has appropriate interaction properties such as:

cursor: pointer;
pointer-events: auto;

Only add z-index/positioning overrides if actually necessary.

Do NOT use an arbitrarily huge z-index unless investigation proves an overlay is the cause.

==================================================
ROBUST CLICK EVENT
==================================================

The click handler MUST log immediately as its first operation:

console.log('[LFDashboard] Dashboard button clicked.');

This log must happen BEFORE:

repository detection
URL construction
window.open
server requests
authentication logic

Therefore we can distinguish:

click failure

from:

repository/navigation failure.

Use a robust event registration strategy.

If direct:

button.addEventListener('click', handler);

is reliable, use it.

If Laserfiche replaces navbar nodes dynamically, use delegated event handling from a stable ancestor or window.document.

For example, conceptually:

stableAncestor.addEventListener('click', function (event) {
    var target = ...;

    if (target matches Dashboard button or is inside it) {
        handleDashboardClick(event);
    }
});

Do not register duplicate handlers.

If both direct and delegated handling are used for resilience, ensure a single physical click cannot open Dashboard twice.
