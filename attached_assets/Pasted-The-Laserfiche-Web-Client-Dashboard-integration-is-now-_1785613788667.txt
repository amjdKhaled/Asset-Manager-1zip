BUG — ONE CLICK OPENS DASHBOARD TWICE
==================================================

Currently, when I click the Dashboard button ONCE in the Laserfiche Web Client, TWO Dashboard browser tabs/windows are opened.

The screenshot confirms that a single click results in two Dashboard pages being launched.

This must be fixed.

Expected behavior:

ONE physical click on Dashboard
        ↓
ONE click handler execution
        ↓
ONE repository detection
        ↓
ONE Dashboard URL generation
        ↓
ONE window.open/navigation
        ↓
EXACTLY ONE Dashboard tab/window

Never two.

==================================================
LIKELY CAUSE
==================================================

The previous fix intentionally introduced multiple click-handling mechanisms for reliability:

1. Capture-phase delegated listener.
2. Direct button click listener.
3. Possibly anchor/window.open fallback logic.

Now that clicking works, these mechanisms may both be handling the same physical event.

Audit the ACTUAL current implementation of:

src/LFPortal.Web/wwwroot/js/lf-webclient-button.js

Do not guess.

Trace exactly how many times onDashboardClick() is invoked from one physical click.

Also verify whether:

- capture listener invokes it once
- direct listener invokes it again
- MutationObserver creates duplicate handlers
- duplicate script execution registers listeners twice
- both window.open() and the anchor fallback execute
- multiple Dashboard buttons exist invisibly
- Laserfiche navbar re-rendering causes duplicate registrations

==================================================
REQUIREMENT — SINGLE CLICK GUARANTEE
==================================================

Refactor the event handling so there is ONE authoritative click path.

Prefer the simplest reliable architecture.

Since the capture-phase delegated listener solved the Laserfiche click interception problem, prefer keeping ONE delegated capture-phase handler and removing redundant direct click execution if it is no longer necessary.

For example, the architecture should conceptually become:

Browser document
      ↓
ONE capture-phase delegated listener
      ↓
Detect [data-lf-dashboard-button="true"]
      ↓
handleDashboardClick()
      ↓
ONE window.open()

Do not keep multiple independent handlers unless absolutely necessary.

==================================================
ADD A DUPLICATE-CLICK SAFETY GUARD
==================================================

Even after simplifying the event architecture, add a small defensive guard against duplicate execution of the same physical click.

For example:

- event identity guard
OR
- very short click lock/debounce

The guard must prevent duplicate execution caused by Laserfiche DOM/event behavior.

It must NOT prevent the user from legitimately clicking Dashboard again later.

A short lock such as approximately 300–500 ms is acceptable.

Conceptually:

if (launchInProgress)
    return;

launchInProgress = true;

open Dashboard once;

setTimeout(() => {
    launchInProgress = false;
}, 500);

Use the cleanest implementation appropriate for the existing code.

==================================================
POPUP FALLBACK
==================================================

window.open(...)

The fallback must execute ONLY when the primary open operation actually fails.

There must never be:

window.open(...)
+
anchor.click()

for the same successful launch.
