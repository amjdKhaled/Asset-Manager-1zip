I want to redesign the search experience of the GovSearch AI platform into a single unified intelligent search system.

Current state:

* Hybrid Search
* Semantic Search
* Keyword Search
* NL Search

These four search modes currently appear as separate buttons that users must manually choose from.

New Requirement:
Remove all search mode selection buttons from the user interface.

The user should see only ONE search box:

"Smart Search"

The user must never need to decide which search engine to use.

Instead, the system should automatically analyze the query and intelligently route it to the appropriate search engines behind the scenes.

---

## SMART SEARCH ARCHITECTURE

When a user submits a query, the platform should execute a Unified Search Pipeline.

Step 1:
Analyze the query using AI intent classification.

Determine whether the query is:

* Metadata-focused
* Keyword-focused
* Semantic/concept-focused
* Natural language repository request
* Mixed query

Examples:

Query:
"Contract 12345"

Intent:
Keyword Search

---

Query:
"Remote work policy"

Intent:
Semantic Search

---

Query:
"All approved HR documents from 2025"

Intent:
Metadata + Laserfiche Search

---

Query:
"Show me contracts related to Aramco signed in 2025"

Intent:
Hybrid + Metadata + Laserfiche Search

---

STEP 2
MULTI-ENGINE EXECUTION
----------------------

Instead of choosing a single engine, Smart Search should be capable of executing multiple search engines simultaneously.

Available engines:

1. Semantic Search
2. Hybrid Search
3. Keyword Search
4. Laserfiche Natural Language Search
5. Metadata Search (NEW)

The AI should decide which engines are relevant.

Example:

User:
"Aramco contracts"

Execute:

* Semantic Search
* Keyword Search
* Metadata Search

Combine results.

---

STEP 3
ADD NEW METADATA SEARCH ENGINE
------------------------------

Implement a dedicated Metadata Search engine.

Search directly against Laserfiche metadata fields.

Examples:

Department = HR

Year = 2025

Status = Approved

Document Type = Contract

Template Fields

Repository Metadata

Metadata Search must support:

* Exact match
* Partial match
* Date ranges
* Multiple field filters

This engine should query Laserfiche metadata directly using available APIs.

---

STEP 4
RESULT FUSION
-------------

Merge all returned results from all engines.

Remove duplicates.

Normalize scores.

Create a unified ranking algorithm.

Ranking factors:

* Semantic similarity
* Keyword relevance
* Metadata match quality
* Laserfiche relevance score
* Document freshness
* Document popularity (if available)

Return only the best ranked results.

---

STEP 5
EXPLAINABILITY
--------------

For every search result display:

Why this document matched.

Examples:

Matched by:

* Semantic similarity
* Metadata: Department=HR
* Keyword: Contract

or

Matched by:

* Laserfiche full-text index
* Metadata: Year=2025

This improves trust and transparency.

---

STEP 6
SEARCH PERFORMANCE
------------------

Execute searches in parallel.

Use Promise.all or equivalent parallel processing.

Implement caching for repeated queries.

Add search timeout protection.

Avoid blocking UI while waiting for all engines.

---

STEP 7
USER EXPERIENCE
---------------

Remove:

* Hybrid Search button
* Semantic Search button
* Keyword Search button
* NL Search button

Replace with:

Smart Search

Placeholder:

"Search documents, metadata, policies, contracts, procedures, and repository content..."

The user experience should feel similar to modern AI enterprise search systems such as Microsoft Copilot, Elastic AI Search, and Glean.

---

STEP 8
BACKWARD COMPATIBILITY
----------------------

Do not remove existing search engines.

Keep all existing implementations.

Only move them behind the new Smart Search orchestrator.

Existing APIs should continue to work.

The new Smart Search layer should sit on top of the current architecture and intelligently coordinate all search engines.

---

## SUCCESS CRITERIA

A user can type any natural language query into a single search box and receive the best possible results from all available search technologies without needing to understand or manually select search modes.
