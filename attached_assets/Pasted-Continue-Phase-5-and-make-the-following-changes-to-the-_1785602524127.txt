1. ACTIVE REPOSITORY MUST COME FROM LASERFICHE
==================================================

The Dashboard button inside Laserfiche Desktop Client must automatically open the Dashboard for the repository from which the button was clicked.

The user must NOT need to manually configure Repository ID in Dashboard Settings every time they switch repositories.

Expected behavior:

Example:

If the user is currently inside:

LFNewRepoWF

and clicks the Dashboard button:

→ Dashboard opens using LFNewRepoWF.

If the user switches in Laserfiche Desktop Client to:

NewEmployeeTest

and clicks Dashboard:

→ Dashboard opens using NewEmployeeTest automatically.

If the user switches to another repository:

→ Dashboard must use that repository automatically.

The repository context must come from Laserfiche Desktop Client at button-click time.

Do NOT hard-code a repository.

Do NOT overwrite the globally saved Repository ID just because the Desktop Client opened another repository.

The repository passed by the Desktop Client should act as the active repository for that Dashboard session/request.

Preferred flow:

Laserfiche Desktop Client
        ↓
Dashboard toolbar button
        ↓
Read active/current Laserfiche repository
        ↓
Launch Dashboard URL with repository context
        ↓
Dashboard resolves that repository
        ↓
Dashboard / Archive / Settings use the same active repository context

For example, a URL may conceptually look like:

https://localhost:PORT/?repository=LFNewRepoWF

However, use the architecture that best fits the existing application.

Repository resolution priority should be:

1. Repository supplied by Dashboard.DesktopExtension
2. Current Dashboard session repository
3. Saved/default repository from Settings as fallback

The repository context must persist while navigating between:

Dashboard
Archive
Settings

Do not require ?repository=... to be manually added to every link if a session-based implementation is cleaner.

IMPORTANT:
Settings such as API Server URL, credentials, timeout, etc. may remain global.

The dynamic value is the ACTIVE REPOSITORY.
